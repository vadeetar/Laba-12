* **Задание 7: Unit-тесты**. Написано 7 комплексных тестов. Итоговое покрытие кода (Coverage) составило **92%**.
* **Задание 8: Исправление галлюцинаций**. Выявлена и исправлена ошибка ИИ, предложившего несовместимую версию bcrypt для Python 3.14. Зафиксирована версия `bcrypt<4.0.0`.

* ### Задание 2: Code Review (Анализ сгенерированного кода)
В ходе разработки был проведен аудит кода ИИ и внесены следующие правки:
1. **app/models/stay.py** * *Проблема:* ИИ использовал устаревший `datetime.utcnow` как default.
   * *Исправление:* Заменено на `lambda: datetime.now(timezone.utc)`.
2. **requirements.txt**
   * *Проблема:* Модель предложила `bcrypt`, конфликтующий с Python 3.14.
   * *Исправление:* Жестко зафиксирована версия `bcrypt<4.0.0`.
3. **app/routers/bookings.py**
   * *Проблема:* ИИ генерировал бизнес-логику прямо в роутере.
   * *Исправление:* Логика вынесена в класс `BookingService` (Service Layer).
4. **tests/conftest.py**
   * *Проблема:* ИИ не импортировал все модели до `create_all()`, из-за чего падала in-memory БД (OperationalError).
   * *Исправление:* Добавлен явный импорт всех моделей перед инициализацией базы.
5. **app/core/security.py**
   * *Проблема:* Отсутствовала привязка JWT-токена к `timezone.utc`.
   * *Исправление:* Переписана логика генерации `expire` на timezone-aware.

### Задание 8: Анализ галлюцинаций ИИ (Эссе)
В процессе разработки была выявлена классическая «галлюцинация» ИИ: модель предложила использовать стандартную команду установки `bcrypt`, игнорируя тот факт, что в Python 3.14 изменены механизмы работы с C-расширениями. ИИ просто не «знал» о последних изменениях в языке.

**Вывод:** Распознать ошибку помог анализ логов сборки Docker. Это подтверждает, что при «vibe coding» разработчик должен выступать в роли квалифицированного цензора, а не просто копировать текст. Без ручной фиксации версии библиотеки проект бы не запустился.
